# Simulation standard

Every page in this lab is a single, self-contained HTML file that shares one
shell. This document is the contract: follow it and a new simulation drops into
the catalog with no extra wiring.

- Shared shell: `assets/lab.css`, `assets/lab.js`
- Starter file: `assets/_template.html` (copy it, don't edit it)
- Catalog is generated by `update_index_links.py`

---

## 1. Where files go

```
MATH_lab/
├── index.html                     generated landing page — never hand-edit the catalog block
├── update_index_links.py          builds the catalog from this folder tree
├── assets/
│   ├── lab.css                    shared shell styles
│   ├── lab.js                     shared theme, header, canvas helpers
│   └── _template.html             starter page (leading _ keeps it out of the catalog)
├── 1226/                          one folder per course = one collection
│   ├── _collection.json           collection title, description, order
│   ├── curve_explorer.html
│   └── curve_explorer.json        optional page metadata
└── <course>/
    ├── <simulation>.html
    └── <simulation>.json          optional but recommended
```

Rules the generator enforces:

| Name | Behaviour |
|---|---|
| `index.html` at the root | Skipped — it is the catalog itself |
| Files or folders starting with `_` | Skipped — use for templates, drafts, retired pages |
| Files or folders starting with `.` | Skipped |
| Any other `*.html` | Becomes a catalog card |

So to retire a page without deleting it, rename it `_old_name.html`.

## 2. Metadata

The catalog reads, in priority order:

1. `<page>.json` sidecar next to the page
2. `<title>`, `<meta name="description">`, `<meta name="keywords">` inside the page
3. Fallbacks: the filename humanised, and a generic description

The sidecar (recommended — it keeps prose out of the markup):

```json
{
  "title": "Curve Explorer",
  "description": "Trace polar and parametric curves and watch enclosed area and arc length accumulate as the parameter advances.",
  "tags": ["Calculus", "Polar", "Parametric"]
}
```

Tags become the filter chips on the index. Keep them to 2–3 words, reuse
existing topics where possible, and use title case.

A collection is described by `_collection.json` in its folder:

```json
{
  "title": "1226",
  "description": "Simulations grouped for the 1226 course.",
  "order": 1
}
```

`order` controls chapter position (default `0`; the root collection is always
first). Lower sorts earlier.

## 3. Page skeleton

Copy `assets/_template.html`. The order matters:

```html
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">
  <title>…</title>
  <meta name="description" content="…">
  <meta name="keywords" content="…">

  <link rel="stylesheet" href="…fonts…">
  <link rel="stylesheet" href="../assets/lab.css">

  <!-- must run before first paint -->
  <script>
    try {
      var saved = localStorage.getItem("mathlab-theme");
      if (saved === "dark" || saved === "light")
        document.documentElement.setAttribute("data-theme", saved);
    } catch (e) {}
  </script>

  <style>/* page-specific rules only */</style>
</head>
```

Then, in order:

1. `header.masthead` — copy verbatim; only the stack chip text changes
2. `div.shell`
   - `aside.panel` — controls
   - `main.main` — hero, `section.stats`, chart cards
3. `footer.foot`
4. `<script src="../assets/lab.js"></script>`
5. `<script>/* page logic */</script>`

**Never** re-declare tokens, `.masthead`, `.panel`, `.stats`, `.chart-card` or
`.foot` in the page. If something genuinely needs a new colour, add a token to
`lab.css` in all three places (light root, dark media query, dark attribute).

## 4. Component contract

### Masthead

The left label is **not** hardcoded. `MathLab` fills `#collectionName` from the
page's folder name, then upgrades it with `_collection.json` if reachable. The
right side holds: stack chip (`.chip.optional`, hidden under 720px), credit,
theme toggle (`#themeBtn`), home button (`../index.html`).

The home link is relative — a page nested one folder deep uses `../index.html`.

### Control rail

```html
<div class="field">
  <div class="field-row">
    <label for="x">Label</label>
    <span class="value-pill" id="xPill">0</span>
  </div>
  <input class="input" id="x" type="number" …>
  <p class="field-hint">One line of guidance.</p>
</div>
```

Available controls:

| Class | Use |
|---|---|
| `.input` | text, number, expression fields |
| `.select-wrap > select` | dropdowns |
| `.range` | sliders — set `--fill` to the percentage for the filled track |
| `.chips` / `.chip-btn` | preset buttons |
| `.center-control` / `.center-step-btn` | numeric field with decrement/increment |
| `.interval-row` | `a → b` pair |
| `.ghost-btn` | small secondary action in a field row |
| `.run-btn` | the one primary action, full width |
| `.panel-note` | closing explanation |

Errors: add `.bad` to the offending input and show text in `.field-hint.error`.
Do not use `alert()`.

### Stat strip

Exactly **five** cells — the grid is `repeat(5, …)` and is not auto-fitting:

```html
<section class="stats" aria-label="Summary">
  <div class="stat">
    <span class="stat-label">Max remainder</span>
    <span class="stat-value" id="statErr">—</span>
    <span class="stat-sub">on the view window</span>
  </div>
  …
</section>
```

The first cell has no special styling; all five look alike. Values are
monospace and tabular, so keep them short enough to fit (~12 characters).

### Chart card

```html
<section class="chart-card" aria-labelledby="chartTitle">
  <div class="chart-head">
    <h2 class="chart-title" id="chartTitle"><span class="idx">01</span>Plot</h2>
    <div class="legend" aria-hidden="true">
      <span><i class="swatch s-f"></i>f(x)</span>
      <span><i class="swatch dot s-c"></i>point</span>
    </div>
  </div>
  <div class="plot" id="plotWrap"><canvas id="plot" role="img" aria-label="…"></canvas></div>
  <div class="chart-foot"><span>samples <b id="footSamples">—</b></span></div>
</section>
```

Legend vocabulary — use these, never bespoke colours:

| Class | Meaning | Colour token |
|---|---|---|
| `.swatch.s-f` | the function / full path | `--series-f` |
| `.swatch.s-p` | the approximation / traced part | `--series-p` |
| `.swatch.s-r` | remainder / error | `--series-r` |
| `.swatch.s-d` | tolerance / threshold | `--danger` |
| `.swatch.s-c` | current point / centre | `--center` |
| `.swatch.s-muted` | structural marker | `--muted` |
| `.swatch.dot` | point marker (filled circle) | inherits |
| `.swatch.dashed` | dashed line | inherits |
| `.swatch.band` | translucent region | inherits |
| `.swatch.faint` | secondary / ghosted line | inherits |

Multiple charts stack in `main.main` with the cards' own `gap`.

## 5. JavaScript

`lab.js` exposes:

```js
MathLab.theme()            // "light" | "dark"
MathLab.toggleTheme()      // flip, persist, notify
MathLab.onTheme(fn)        // re-render on theme change
MathLab.collection()       // { name, description, folder }
MathLab.format(v, sig)     // 4-sig-fig string with a real minus sign
MathLab.canvas.lab(canvas) // { fit(), clear(), w, h, dpr, ctx }
```

Theme handling is automatic for the toggle button. **If a page draws on canvas
it must call `MathLab.onTheme(render)`** and read colours from CSS variables at
draw time — never cache them, or dark mode will keep the light palette:

```js
function palette() {
  var s = getComputedStyle(document.documentElement);
  return { f: s.getPropertyValue("--series-f").trim(), /* … */ };
}
```

Canvas lifecycle:

```js
var chart = MathLab.canvas.lab(canvas);
function render() {
  chart.fit();      // handles devicePixelRatio and container size
  chart.clear();
  // draw using chart.w, chart.h, chart.ctx
}
new ResizeObserver(render).observe(plotWrap);   // or window resize
```

## 6. Accessibility and responsiveness

Required:

- `<canvas role="img" aria-label="…">` describing what the plot shows
- Every input has a `<label for>`; icon-only buttons have `aria-label`
- Live readouts that change on input use `aria-live="polite"`
- Toggles use `aria-pressed`
- Visible focus comes from `:focus-visible` in `lab.css` — don't remove it
- Respect `prefers-reduced-motion`: skip animations, jump to the final state
- No horizontal scroll at 320px

Breakpoints handled by `lab.css`: 1220 (narrower rail), 960 (stack to one
column, stats 2×3), 720 (smaller type/plots), 430 (compact masthead).

## 7. Content style

- Sentence case in prose. No ALL CAPS except the small mono labels, which the
  stylesheet applies via `text-transform`.
- Titles are nouns: "Curve Explorer", not "Explore Curves!"
- No marketing filler. Explain what the control does and what the plot shows.
- Spell out symbols on first use: "angle θ, radians".
- Use a real minus sign `−` (U+2212) in displayed numbers —
  `MathLab.format()` does this for you.

## 8. Adding a simulation

```bash
cp assets/_template.html 1226/my_new_sim.html
# replace __TITLE__, __DESCRIPTION__, __TAGS__, __STACK__, __EYEBROW__,
# __LEDE__, __FORMULA__, then write the model and render() call

cat > 1226/my_new_sim.json <<'JSON'
{
  "title": "My New Sim",
  "description": "One sentence on what a student can move and see.",
  "tags": ["Calculus", "Derivatives"]
}
JSON

python3 update_index_links.py          # rewrites index.html
python3 update_index_links.py --check  # exit 1 if the catalog is stale (CI)
```

## 9. Pre-merge checklist

- [ ] Loads with no console errors
- [ ] Renders in light and dark; toggling recolours canvas work
- [ ] Works at 320px with no horizontal scroll
- [ ] Keyboard reaches every control; focus is visible
- [ ] Invalid input shows an inline message, not a broken plot
- [ ] Reduced motion does not animate
- [ ] Sidecar JSON present, tags match existing topics
- [ ] `python3 update_index_links.py --check` passes
- [ ] No local paths, no `TODO`, no leftover `console.log`
